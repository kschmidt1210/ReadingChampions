### T1. Rename `src/proxy.ts` → `src/middleware.ts` so Next.js middleware actually runs

- **Problem:** Next.js only auto-executes a file named `middleware.ts` exporting `middleware` (or default). The file is currently `src/proxy.ts` exporting `proxy()`, so `updateSession` (Supabase session refresh, `src/lib/supabase/middleware.ts`) never runs. Users get silently logged out when their access token expires.
- **Change:** Rename the file with `git mv src/proxy.ts src/middleware.ts`. Inside, rename the exported function `proxy` → `middleware`. Keep the `config` matcher export exactly as is.
- **Accept:** `src/middleware.ts` exists exporting `middleware` and `config`; `src/proxy.ts` is gone; `npm run build` output lists the middleware (build log shows a `ƒ Middleware` entry / `middleware` in the route summary).
- **Verify:** `npm run build` succeeds and mentions middleware.

### T2. Fix `recalculateSeasonPoints` scoring every book as 0 pages ⚠️

- **File:** `src/lib/actions/admin.ts` (~line 224).
- **Problem:** The entries query selects `"*, book:books(country)"` but the loop below reads `(entry.book as any)?.pages ?? 0`. `pages` is never fetched, so every completed book recalculates with 0 pages and the admin "Recalculate" button **rewrites stored points to wrong, lower values**.
- **Change:** Change the select string to `"*, book:books(country, pages)"`.
- **Also add a regression test:** create `src/lib/__tests__/recalculate.test.ts`. The scoring function `calculateBookScore` in `src/lib/scoring.ts` is pure — at minimum, add a test asserting that a completed 300-page book scores the same via the recalculation code path inputs (pages from the book row) as via direct calculation with pages=300, and that pages=0 produces a lower score (documents why the fetch matters). If extracting the per-entry recalculation math into a small pure helper makes it testable, do so **within `admin.ts` scope only** (export a helper like `computeEntryScore(entry, book, rules, isNewCountry)`); keep behavior identical.
- **Pitfall:** Do NOT change any other part of the recalculation logic (country ordering, DNF handling). Compare with the known-good equivalent in `scripts/recalculate-points.ts` (which correctly fetches `book:books(title, pages, country)`) if unsure.
- **Accept:** select includes `pages`; test exists and passes.

## Phase 2 — Security & backend hardening

### T3. Add server-side input validation with zod

- **Files:** all of `src/lib/actions/*.ts` (`books.ts`, `admin.ts`, `auth.ts`, `community.ts`, `import.ts`, `managed-players.ts`, `organizations.ts`, `profile.ts`, `reviews.ts`). `zod` v4 is already in `package.json` — it is currently never imported.
- **Problem:** Actions trust client input: `formData.get(...) as string` with no null checks, unbounded numbers (negative pages, NaN ratings), unvalidated strings.
- **Change:** For each exported server action, define a zod schema at the top of the file and `safeParse` the inputs before use. Return the action's existing error shape (look at how each action currently returns errors — most return `{ error: string }` or throw; match each file's existing convention) with a human-readable message on failure. Minimum rules:
  - `pages`, `pagesRead`: integer, `min(1)`, `max(20000)` (pagesRead `min(0)`).
  - `rating`: number `min(0).max(10)` or null/undefined.
  - `title`, `author`, org name, genre name, series name: trimmed string, `min(1)`, `max(300)`; genre/org names `max(80)`.
  - emails: `z.string().email()`; passwords: `min(8)`.
  - IDs (`orgId`, `seasonId`, `entryId`, etc.): `z.string().uuid()`.
  - Community: post body `min(1).max(5000)`; comment `max(2000)`; reaction emoji — replace the current length-only check in `community.ts` (~line 430) with a regex that only accepts emoji code points, e.g. `/^\p{Extended_Pictographic}(‍\p{Extended_Pictographic}|️|\p{Emoji_Modifier})*$/u`.
  - Status: `z.enum(["completed", "reading", "did_not_finish"])` (confirm the exact enum values used in `src/types/database.ts` first and use those).
- **Pitfall:** Do not change any action's success return shape — UI components depend on them. Validation failures must not crash pages; they must surface as the existing error pattern (which becomes a toast in most panels).
- **Accept:** every exported action parses its inputs; `grep -rn "from \"zod\"" src/lib/actions | wc -l` ≥ 9; type check, lint, tests, build all pass.
